# Orchestration notes for #78

## CHANGELOG.md

Under `## [Unreleased]` → `### Fixed`:

- **A file production deletes *while the extraction runs* no longer aborts the finished run at its last step.** The Extractor widened `strict: false` (Kntnt/kntnt-extractor#31, its ADR-0026): it used to mean only "a file that vanished between the `GET /files` walk and the `POST` is skipped", and now also covers a file that vanishes during packaging, hours after the `201` was answered. `skipped_files` therefore stopped being settled at create — the `201`'s list is a lower bound, and the terminal poll's is the whole of it. This client froze the lower bound: `extract-submit` wrote the `201`'s list into `<scratchpad>/extract-job.json`, the poll observed the current list and discarded it, and `extract-transfer` told the unseal to expect the submitted selection minus the frozen one. `unseal.py` compares the container's file names to that list with **strict equality**, so a mid-run skip was not an under-count but a refusal: `FAILED` after the multi-gigabyte download, after the whole extraction — six hours spent and lost at the final step, on the production run that motivated the plugin-side change. The list was already on this machine; what was missing was the step that carried it to the unseal. `skills/clone/scripts/poll_extraction.py` now takes an optional `--job-record <path>` and, on a terminal verdict, folds the skip list it observed into that record as `packaging_skipped_files`, beside the create's own `skipped_files`; `extract-transfer` subtracts both and goes on taking its lists from the job record alone, its hard rule literally unchanged. **The merge belongs to the deterministic helper rather than to the orchestrator's prose**, because prose an agent must execute correctly at a six-hour run's last step cannot be pinned by a test — and these four properties each are: the argument is optional and absent by default, so the preflight's record-less poll behaves exactly as before; the merge is a union that never shrinks, since the client must not depend on the plugin appending rather than rewriting; it is idempotent, because a lost poller is a re-poll of the identical command; and only a terminal verdict writes, so a transport failure or an exhausted budget touches nothing. **The two causes stay apart** in the record and in the run report — a file deleted while the client was looking at it, and production mutating hours into the extraction, which is the only place an operator could learn the latter — and are unioned only where the unseal needs one list. A fifth degraded-behaviour bullet fires when `discovery.honours` does not name `packaging_skips`: such a host cannot produce a mid-run skip, the merge is a no-op there, and what it cannot tell you is whether production changed during the hours the run took. **The Extractor's `API_VERSION` stays 7 and this client's verified ceiling stays 7** — Kntnt/kntnt-extractor#59 argues for 8 on that repository's ADR-0018 second ground, already-shipped logic made unsafe undetectably, and the condition is met while the ground is empty: that protection exists to reach clients in the wild and there are none. The ordering discipline replacing it is to land this before production's Extractor is upgraded, which costs nothing since the fix is a no-op against the build now in production. See [ADR-0036](docs/adr/0036-the-poll-helper-merges-the-packaging-time-skips.md) ([#78](https://github.com/Kntnt/kntnt-wp-skills/issues/78)).
